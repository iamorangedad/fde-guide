# 9.1 何时微调,以及损失怎么定义

> [🏠 返回主页](../../README.md) · [返回本章](README.md)

## 先修

条件概率、第 3 章的 RAG 与评测。PyTorch 的 `CrossEntropyLoss` 把 `ignore_index=-100` 排除在损失之外,文档见延伸阅读。

## 学习目标

- 用"知识是否变化、行为是否稳定、权重是否放得进内存"选择方法
- 写出解码器因果语言模型的下一个 token 负对数似然
- 解释标签移位,以及为什么提示 token 可以不进入损失

## 定义

**提示(prompting)**不改权重。它适合格式已经能稳住、或者样本少到无法代表任务的情况。

**RAG**不改权重,在请求时把外部文本放进上下文。它适合事实会变、答案必须能指回原文、以及不同用户看到的文档权限不同。检索失败和生成失败要分开评,这是第 3 章的诊断。

**监督微调(SFT)**用标注的输入输出对更新模型,使 \(p(\mathrm{回答}\mid\mathrm{上下文})\) 靠近标注。它适合提示反复失败的稳定行为:引用格式、字段顺序、工具参数的形状。它不适合当作"把制度背进权重"的捷径,制度下周就会改。

**全量微调**更新全部(或几乎全部)权重。表达力最大,优化器状态也最大,见第 10 章。

**LoRA** 冻结原矩阵 \(W\),只训练低秩增量。**QLoRA** 把冻结的基座放在低比特表示里,以便基座本身放不进 GPU。两者都是 SFT 的参数化方式,不是另一种任务。

| 你真正要的 | 先考虑 | 不要先考虑 |
|---|---|---|
| 答案必须引用某份会更新的制度 | RAG,权限在检索时过滤 | 把制度背进 SFT |
| 换一种说法就能稳定输出 JSON | 提示和校验器 | 训练 |
| 提示和校验仍不稳定,且有干净的输入输出对 | SFT;权重放得下就全量或 LoRA | 用更大的提示碰运气 |
| 冻结的 fp16 基座也放不进训练卡 | QLoRA 或换更小的模型 | 在 CPU 上假装自己在做 7B 全量训练 |
| 高风险动作(付款、写库) | 程序门禁和人工确认 | 指望损失学不会危险动作 |

PEFT 文档概述 LoRA 时说,在其讨论的设定里 LoRA 的表现可以接近全量微调。那是方法论文和库文档的概括,不是你的保留集。没有评测就不能借用这句话。

## 原理:下一个 token

解码器模型把一段 token \(x_1,\ldots,x_T\) 的概率分解成

$$
p(x) = \prod_{t=2}^{T} p(x_t \mid x_{<t})
$$

训练用教师强制:输入是标注前缀,不是上一步采样出来的 token。单个位置的损失是 \(-\log p(x_t\mid x_{<t})\)。平均时只对你指定的位置求平均。

实现上,位置 \(t\) 的 logits 用来预测位置 \(t+1\) 的 token。经典写法是取 `logits[..., :-1]` 对齐 `labels[..., 1:]`。因此 `labels[0]` 没有前一个位置,不进入损失。Transformers 5.22 的 `ForCausalLMLoss` 用另一种等价实现:在 labels 右侧填充一个 `ignore_index`,再取 `labels[..., 1:]`,使最后一个 logit 对齐到这个填充值并被忽略。参与损失的配对仍然是"logits\([t]\) 预测原来的 labels\([t+1]\)"。本仓库的 [loss_mask.py](examples/loss_mask.py) 采用经典切片,并在测试里锁定数值。

**提示屏蔽**:若目标是学会回答而不是复述问题,就把 system、user 和角色标记的 label 设为 -100,只保留 assistant 正文和停止符。长提示否则会主导平均损失,梯度主要在学复制。若目标是继续预训练整篇文档,就不要做这层屏蔽。两种目标不能在同一次平均里混用还不写出来。

填充位置同样是 -100,并且 `attention_mask` 为 0。只改其中一个,模型仍可能在填充 token 上看见或预测它们。

### 演算

序列 labels = \([-100,-100,1]\),每个位置的 logits 都是 \([0,1]\),词表大小 2。

移位后,只有原来的最后一个 label `1` 参与。对应的 logit 行是第二个位置的 \([0,1]\)(经典切片里,预测 label\([2]\) 的是 logits\([1]\))。

$$
\log Z = \log(e^{0}+e^{1}),\quad \mathrm{NLL} = -(1-\log Z)
$$

把第一个位置的 logits 改成任意值,平均损失不变,因为那个位置的 label 在移位后仍被忽略。把中间那个 label 从 -100 改成 1,就多了一个正的 NLL,平均损失上升。测试 `test_prompt_is_prefix_and_loss_ignores_it` 锁定了"被屏蔽位置的 logits 不进入平均"和"取消屏蔽会使损失变大"。

## 实例

教学模板只有一份实现,[chat_template.py](examples/chat_template.py):

```text
<|system|>
{system}
<|user|>
{user}
<|assistant|>
{assistant}<|eot|>
```

推理时渲染到 `<|assistant|>\n` 为止,不包含答案,也不包含 `<|eot|>`。训练字符串必须以这段提示为前缀,分词之后仍然是前缀。这个不变量一旦破坏,屏蔽长度就会切到答案中间或切进问题里。

字符分词器是为了离线演示。生产训练必须使用目标模型自带的分词器和 `apply_chat_template`。模板差一个控制符,条件分布就不是你以为的那个。Transformers 的聊天模板文档把这一点说成训练和推理的同一条字符串;TRL 还要求,若只对 assistant 计算损失,模板里要有生成区间标记。我们的教学模板用显式的前缀长度达到同一目的,不假装自己是某个发布模型的 Jinja 模板。

## 排障

| 现象 | 原因 |
|---|---|
| 训练损失很低,回答却在背题干 | 没有屏蔽提示,损失被复制题干主导 |
| 推理时模型先复读用户的话 | 训练模板和 `add_generation_prompt` 不一致 |
| 填充越长损失越怪 | 填充的 label 不是 -100,或 attention mask 仍是 1 |
| 损失是 NaN | 学习率过大、fp16 溢出又没有缩放。先在 fp32 小模型上确认屏蔽是对的 |
| 把 \(\log V\) 附近的损失说成"已经学会" | 随机初始化的均匀分布就是这个量级。要看保留集上的任务指标 |

## 练习

1. 一个样本有 30 个提示 token 和 2 个回答 token,全部进入损失。回答每个 token 的负对数似然是 2,提示每个是 0.1。平均损失是多少?若只保留回答,平均损失是多少?哪一个更接近"回答得好不好"?
2. 客户说"把员工手册做成聊天机器人,手册每月更新,回答要带章节号"。你会把哪一部分放进 RAG,哪一部分才可能值得 SFT?
3. 为什么 `labels[0]` 写成真实 token 也不会影响经典切片下的损失?

### 参考解答

1. 全部进入时,总和是 \(30\times 0.1 + 2\times 2 = 7\),平均是 \(7/32 = 0.21875\)。只保留回答时平均是 2。0.22 看起来"更好",但它几乎只反映提示很容易被复制。任务若是回答,第二个数才是目标。
2. 手册正文和章节号的事实放进 RAG,并在检索时做权限过滤。若模型始终不写章节号、提示和少样本都稳不住,可以用少量"问题 → 带章节号的回答"做格式 SFT,回答中的事实仍应来自检索到的段落,而不是背进权重。评测要同时看引用是否存在、引用是否支持回答。
3. 经典实现对齐的是 `labels[1:]`。下标 0 被切掉。Transformers 5.22 的填充实现同样不让原 labels 的第 0 个位置去监督任何一个 logit。所以屏蔽循环即使从 0 开始写成 -100,也只是为了读代码的人看得懂,数值上第 0 位本来就不参与。

## 小结

方法选择看的是知识、行为和内存,不是"我们是不是一家 AI 公司"。损失是移位后的条件负对数似然,而且只在你没有标成 -100 的位置上。模板是训练分布的一部分,必须和推理用同一段前缀。
