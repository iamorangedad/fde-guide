## 先修

第 4 章的范围和验收,第 3.4 节的实验日志,第 3.5 节的延迟定义。

## 学习目标

- 把一次优化写成六步,并且每一步都有留下的工件
- 用发布门同时卡住正确性、质量和延迟
- 区分"可以上线"和"还需要一次测量"

## 定义

**基线**是改动之前、用同一套题目和同一套成功定义跑出来的记录。没有基线的改进无法归因。

**瓶颈**是基线里占时间或占字节的那一行,而且要能指到公式或剖析,而不是"感觉慢"。

**假设**是一句可以证伪的话:改变哪一个自变量,哪一个指标会朝哪个方向动,其他因素保持不变。

**门**是发布前必须满足的不等式。过不了门就停,不用"线下感觉更好"代替。

**回滚**是已经写好的、把流量切回上一版本的条件,包括谁有权执行、多久之内、切回之后看哪两个指标。

## 六步

```mermaid
flowchart LR
  A[基线] --> B[瓶颈]
  B --> C[单变量假设]
  C --> D[对照实验]
  D --> E[正确性与质量门]
  E --> F[金丝雀 / 回滚]
```

| 步骤 | 留下的工件 | 不合格的样子 |
|---|---|---|
| 基线 | 配置、数据哈希、种子、指标、硬件 | 只有一句"原来大约两秒" |
| 瓶颈 | 字节账或时间线上的一行 | 同时列出五个怀疑对象 |
| 假设 | 一个自变量 | "我们全面优化了系统" |
| 实验 | 与基线只有这一处不同的日志 | 顺手改了学习率和批大小 |
| 门 | 目标任务、遗忘或回归、延迟分位数、错误率 | 只看训练损失 |
| 发布 | 影子流量、金丝雀比例、回滚阈值 | 一次切 100% |

[gates.py](py/gates.py) 把计划里的必填字段和"不能同时改两个因素"做成了检查。观测值用 `evaluate_gates` 对不等式。例如引用精确匹配 `>= 0.9` 且通用探针下降 `<= 0.05`。0.9 和 0.05 是合同或练习里选定的门,不是本节测到的分数。缺观测值就算失败,不能当成 0 分混过去,也不能当成通过。

影子流量:新路径只记录、不返回给用户,用来看错误率和延迟,不让用户承担质量风险。金丝雀:一小部分真实请求走到新路径,比例和持续时间写在计划里。回滚条件用的是已经在基线里测过的同一套指标,避免上线当天才发明定义。

## 正确性和质量不是速度的注脚

一次可以上线的记录至少包含:

- 功能正确:返回结构、权限过滤、引用编号能对上检索到的段落
- 质量:封存集上的忠实度和拒答;若做了微调,再加上第 3.3 节的遗忘探针
- 延迟:TTFT 与端到端的 p50/p95,分位数算法与第 3.5 节一致
- 失败:超时算不算失败,HTTP 200 但答案空算不算失败

速度数字只有在这四项的定义和基线相同的时候才能比较。CUDA 或服务配置没有在目标 GPU 上跑过,报告里就写"未测",不要补一个行业常见的倍数。

## 排障

| 现象 | 处理 |
|---|---|
| 实验"全面变好"但说不出自变量 | 退回基线,拆成多次 |
| 门的阈值在看完结果之后才写下 | 阈值作废。先写门,再跑 |
| 金丝雀期间 p95 变坏但平均变好 | 按事先写的 p95 回滚,不临时改成看平均 |
| 回滚脚本没有在预发演练 | 不算有回滚。演练一次切回,并记录耗时 |
| 客户要求"这周必须上" | 缩小范围,让基线和门仍然存在;不要删掉对照 |

## 练习

1. 计划同时把秩和学习率标成自变量。`validate_experiment_plan` 应该如何处理?你怎么改计划?
2. 观测是引用命中 0.91、探针下降 0.2,门分别是 `>= 0.9` 和 `<= 0.05`。能否金丝雀?缺了哪一条证据仍然不能金丝雀,即使不等式都过了?
3. 为什么影子流量看不出"用户是否采纳回答"?

### 参考解答

1. 检查器会拒绝列表形式的自变量,也会拒绝 `changed_together` 里多于一个因素。改法是拆成两次:第一次只改秩,学习率用基线;第二次在胜出的秩上只改学习率。每次都有自己的假设和门。
2. 引用门通过,探针门失败,不能金丝雀。即便两个不等式都通过,若没有在预发演练过回滚、没有写明超时算不算失败、或延迟分位数还没在同一负载定义下测过,仍然不能把流量切出去。门是必要项的清单,不是唯一的一项。
3. 影子路径的回答没有展示给用户,没有采纳行为。它能看的是系统错误、延迟和离线评分。采纳率要等金丝雀或正式流量,并且要和第 4 章的成功指标用同一个定义。

## 小结

六步里每一步都有工件。门在实验之前写下。速度比较建立在相同的正确性和质量定义上。没有测量的优化保持"未测",回滚在预发就演练过。
